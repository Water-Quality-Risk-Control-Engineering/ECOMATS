## 🚫 为什么不能用Thinking模型?

### 技术原因

**Thinking模型特性**:
- 启用 `enable_thinking=true` 参数
- 模型会先"思考"再输出
- 输出格式包含思考过程和最终答案

**CrewAI要求**:
- 需要 `response_format={"type": "json_object"}` 进行工具调用
- JSON模式要求输出严格遵循JSON格式

**冲突**:
```
DashScope API限制:
enable_thinking=true + response_format=json_object = ❌ 错误
```

---

### 错误示例

```python
# 使用thinking模型时的错误
Error code: 400
{
  'error': {
    'message': '<400> InternalError.Algo.InvalidParameter: 
                Json mode response is not supported when enable_thinking is true',
    'type': 'invalid_request_error',
    'code': 'invalid_parameter_error'
  }
}
```

**影响**:
- ❌ 所有LLM调用失败
- ❌ Agent无法工作
- ❌ 工具调用失败
- ✅ 程序不会崩溃,但无输出

## 🔄 如果需要Thinking能力怎么办?

### 方案1: 混合使用 (推荐)

```python
# 主工作流: qwen-plus (快速+工具调用)
main_llm = CrewLLM(model="qwen-plus", ...)

# 复杂推理任务: thinking模型 (单独调用)
thinking_llm = CrewLLM(model="qwen3-next-80b-a3b-thinking", ...)

# 在特定Agent使用thinking模型
complex_reasoning_agent = Agent(
    role="复杂推理专家",
    llm=thinking_llm,
    allow_delegation=False,  # 禁用委托
    # 不使用工具调用
)
```

---

### 方案2: 任务分离

```python
# 阶段1: 使用qwen-plus完成设计和评估
crew_design = Crew(
    agents=[designer, evaluator],
    tasks=[design_task, eval_task],
    llm=qwen_plus_llm
)

# 阶段2: 使用thinking模型进行深度分析
# (不依赖工具调用,纯推理)
analysis = thinking_llm.call(
    "深度分析上述材料的反应机制..."
)
```

---

### 方案3: Prompt工程

```python
# 在qwen-plus中模拟thinking过程
prompt = """
请按照以下步骤思考:

1. 首先分析问题的关键要素
2. 然后考虑可能的解决方案
3. 评估每个方案的优缺点
4. 最后给出最佳方案

让我们一步步思考...
"""

# qwen-plus也能做推理,只是不显式标注"思考过程"
```
